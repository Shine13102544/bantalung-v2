# ระบบจองโต๊ะคอนเสิร์ต — ร้านบ้านตะลุง

เว็บจองโต๊ะคอนเสิร์ตออนไลน์ มีผังโต๊ะ ระบบตรวจสลิป ตรวจบัตรเข้างาน (สแกน QR) ขายหน้างาน ย้ายโต๊ะ และใบเสร็จ

- **Frontend**: HTML/CSS/JavaScript ล้วน (โฟลเดอร์ `frontend/`)
- **Backend**: Node.js + Express 5 (โฟลเดอร์ `backend/`) รันเป็น Serverless Function บน Vercel (`api/index.js`)
- **ฐานข้อมูล**: Turso (libSQL/SQLite บนคลาวด์) · **รูปภาพ**: Cloudinary

## โครงสร้างโปรเจกต์

```
api/index.js              จุดเข้าของ Vercel (ครอบ backend/server.js)
backend/
  server.js               ตั้งค่า Express, middleware, รวม routes
  db/schema.sql           โครงสร้างตารางทั้งหมด
  db/database.js          เชื่อม Turso + migration แบบมีเวอร์ชัน (SCHEMA_VERSION)
  db/init.js              สั่ง migration ด้วยมือ (npm run db:init)
  middleware/auth.js      ตรวจ JWT และสิทธิ์ (admin / staff)
  routes/                 auth, booking, ticket, receipt, layout, settings, content
  utils/                  sanitize, phone, money, settings (แคช), dbRateLimit, cloudinary, bookings
  seed-admin.js           สร้าง/เปลี่ยนรหัสผ่านแอดมินหรือพนักงาน
  test/                   ชุดทดสอบอัตโนมัติ (node:test)
frontend/
  index.html, app.js      หน้าลูกค้า + โครงหน้าแอดมิน
  admin-tools.js          เครื่องมือแอดมิน (เปิด/ปิดขาย, รายการจอง, ใบเสร็จ, สิ้นสุดคอนเสิร์ต)
  inspect.js              หน้าตรวจบัตร, Walk-in, ย้ายโต๊ะ, สแกน QR
  ticket.html, ticket.js  หน้า "ดูบัตรของฉัน" ของลูกค้า
  vendor/                 jsQR (อ่าน QR) และ qrcode-generator (สร้าง QR) เก็บในโปรเจกต์ ไม่พึ่ง CDN
vercel.json               rewrites + security headers
```

## เริ่มใช้งานในเครื่อง

```bash
npm install
cp backend/.env.example backend/.env     # แล้วแก้ค่าใน backend/.env
npm run seed:admin                       # สร้างบัญชีแอดมิน
npm run seed:staff                       # (ถ้าต้องการ) สร้างบัญชีพนักงานหน้างาน
npm start                                # http://localhost:3000
```

ทดลองโดยไม่ต้องมีบัญชี Turso/Cloudinary: ตั้ง `TURSO_DATABASE_URL=file:./data/dev.db` (ไม่ต้องมี token) — ส่วนอัปโหลดรูปยังต้องใช้ Cloudinary จริง

ถ้าเปิดหน้าเว็บคนละพอร์ตกับ backend (เช่น Live Server) ให้ตั้ง `FRONTEND_ORIGIN` ใน `.env` มิฉะนั้น backend ไม่เปิด CORS

### คำสั่งที่มี

| คำสั่ง | ทำอะไร |
|---|---|
| `npm start` | รัน backend ในเครื่อง |
| `npm run db:init` | สร้าง/อัปเกรดตารางด้วยมือ |
| `npm run seed:admin` / `npm run seed:staff` | สร้างหรือเปลี่ยนรหัสผ่านแอดมิน / พนักงาน |
| `npm test` | รันชุดทดสอบอัตโนมัติ (ใช้ฐานข้อมูลไฟล์ชั่วคราว จำลอง Cloudinary ไม่ต้องต่อเน็ต) |

## ตัวแปรสภาพแวดล้อม (`backend/.env` / Vercel → Settings → Environment Variables)

| ตัวแปร | คำอธิบาย |
|---|---|
| `JWT_SECRET` | ข้อความสุ่มยาว ≥ 32 ตัวอักษร (บน Vercel ถ้าสั้นกว่า 16 หรือเป็นค่าตัวอย่าง ระบบจะไม่ยอมเริ่มทำงาน) |
| `JWT_EXPIRES_IN` | อายุ token (ค่าเริ่มต้น `12h`) |
| `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` | ฐานข้อมูล Turso |
| `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` | คลังรูป |
| `FRONTEND_ORIGIN` | (เฉพาะตอนพัฒนา) โดเมนหน้าเว็บที่อนุญาตให้เรียก API |

## ภาพรวมการทำงาน

**ลูกค้า**: เลือกโต๊ะ → โอนเงินแล้วแนบสลิป → ได้รหัสจอง (ยอดเงินคำนวณที่ server) → รอแอดมินอนุมัติ → เปิดเมนู **"ดูบัตรของฉัน"** กรอก ชื่อ + นามสกุล + เบอร์โทร เพื่อดูสถานะและ QR เข้างาน (หรือแอดมินกด "🔗 ลิงก์บัตร" ที่หน้ารายการจองเพื่อส่งลิงก์ให้ทางแชท)

**หน้าประตู**: เปิดหน้า **ตรวจบัตรเข้าชม** → กด **📷 สแกนบัตร** (ใช้กล้องมือถือ ต้องเปิดผ่าน HTTPS) หรือแตะโต๊ะบนผัง / ค้นหาด้วยชื่อ เบอร์ รหัสจอง · แตะโต๊ะว่างเพื่อขายหน้างาน · ปุ่ม **ย้ายโต๊ะ** ใน sheet รายละเอียด

**หลังจบงาน**: ปุ่ม **สิ้นสุดคอนเสิร์ต** ต้องกรอกรหัสผ่านแอดมิน ระบบสำรองรายการจองทั้งหมดลงตาราง `archives` และดาวน์โหลด CSV ให้ก่อนลบ ถ้าสำรองไม่สำเร็จจะไม่ลบอะไร (ดูข้อมูลเก่าได้ที่การ์ด "ข้อมูลงานที่ผ่านมา") — ผังโต๊ะและใบเสร็จไม่ถูกลบ

## การออกแบบด้านความปลอดภัยที่ควรรู้

- **Rate limit** ของ login, การจอง, ค้นหาบัตร, ยืนยันรหัสผ่าน นับในฐานข้อมูล (`rate_limits`) จึงใช้ได้จริงบน Vercel ที่แต่ละ instance ไม่แชร์ memory ส่วน limiter ทั่วไปใน memory ใช้เป็นด่านหยาบ
- **QR/บัตร** เก็บเฉพาะรหัสลับสุ่ม 128 บิต (`BT1:<token>`) ไม่มีข้อมูลส่วนตัว สแกนซ้ำไม่ได้ (UPDATE เดียวที่มีเงื่อนไข `checked_in = 0`) ถือว่าบัตรเป็นของที่ส่งต่อกันได้ ใครสแกนก่อนได้เข้า — หน้าจอสแกนจึงแสดงชื่อผู้จองให้พนักงานเทียบ
- **ค้นหาบัตร** ต้องตรงทั้ง ชื่อ + นามสกุล + เบอร์ ผิดครบ 5 ครั้งต่อเบอร์ ล็อก 15 นาที และตอบข้อความเดียวกันทุกกรณีที่ไม่พบ
- **สลิปโอนเงิน** อัปโหลดแบบ `authenticated` บน Cloudinary (ต้องมี signed URL — แอดมินเท่านั้นที่ได้) การจองเก่าที่เป็น URL สาธารณะยังเปิดได้ตามเดิม
- **ข้อมูลที่ผู้ใช้กรอก** ผ่าน sanitize ทุกจุด ลิงก์ต้องเป็น http/https ค่า CSS ของผังตรวจรูปแบบ ฝั่งหน้าเว็บแสดงผลด้วย `escapeHtml`/`textContent`
- ยังไม่ได้ตั้ง Content-Security-Policy เพราะหน้าเว็บใช้ inline `onclick` จำนวนมาก (ต้องรีแฟกเตอร์ก่อน) แต่มี security headers อื่นใน `vercel.json` แล้ว
- token แอดมินยังเก็บใน `localStorage` (ถ้ามีช่องโหว่ XSS จุดใดจุดหนึ่ง token รั่วได้) — ทางที่ดีกว่าคือ httpOnly cookie แต่ต้องเพิ่มระบบป้องกัน CSRF

## การตั้งค่าในหน้าแอดมิน (เมนู "การขาย & เอกสาร")

- **เปิดขาย / ปิดการขาย / ขายหมด**: ปุ่มลัดบนเมนูหลัก (server บังคับด้วย ไม่ใช่แค่ซ่อนปุ่ม; ขายหน้างานยังทำได้เสมอ)
- **ตั้งค่าเพิ่มเติม**: เวลาปิดรับจองอัตโนมัติ (เวลาไทย), จำนวนโต๊ะสูงสุดต่อการจอง (ค่าเริ่มต้น 8), ปล่อยโต๊ะอัตโนมัติเมื่อรอตรวจสลิปเกินกี่ชั่วโมง (ค่าเริ่มต้น 0 = ปิด) — ถ้าเปิดต้องตรวจสลิปให้ทันเวลา ไม่เช่นนั้นการจองที่โอนแล้วจะถูกยกเลิก
- **ใบเสร็จ**: เลขที่รันต่อเนื่องรายปี `R2026-0001` ออกแล้วแก้ไม่ได้ ถ้าผิดให้ยกเลิก (void) แล้วออกใหม่ ข้อมูลร้านบนใบเสร็จกรอกตอนออกใบเสร็จครั้งแรก หากใช้เป็นเอกสารทางบัญชี/ภาษีจริงควรปรึกษานักบัญชีว่าต้องมีข้อมูลอะไรบ้าง

## อัปเดตจากเวอร์ชันเดิม (ทำครั้งเดียว)

1. **เปลี่ยน secret ทั้งหมดที่เคยอยู่ใน `backend/.env`** (Turso token, Cloudinary secret, JWT secret) — ไฟล์เคยถูกส่งต่อออกนอกเครื่อง ให้ถือว่าหลุด แล้วอัปเดตค่าใหม่ใน Vercel
2. เอา `node_modules` ออกจาก git (เดิม `.gitignore` เป็น UTF-16 git เลยอ่านไม่ออก):
   ```bash
   git rm -r --cached node_modules
   git add .gitignore .npmrc
   git commit -m "chore: เอา node_modules ออกจาก git และแก้ .gitignore/.npmrc เป็น UTF-8"
   ```
   (ประวัติเก่ายังมีไฟล์เหล่านี้อยู่ ถ้าอยากลดขนาด repo ให้ใช้ `git filter-repo` แยกต่างหาก)
3. ลบ `backend/package.json`, `backend/package-lock.json` และโฟลเดอร์ `backend/node_modules` ในเครื่อง (ตอนนี้ใช้ `package.json` ที่ root ที่เดียว)
4. Deploy ตามปกติ — ฐานข้อมูลจะอัปเกรดเองตอน request แรก (เพิ่มคอลัมน์/ตารางใหม่ สร้างรหัสบัตรและยอดเงินย้อนหลังให้การจองเดิม) ไม่มีข้อมูลเดิมหาย
5. สร้างบัญชีพนักงานหน้างาน: `npm run seed:staff`
6. ทดสอบสแกนบัตรด้วยมือถือจริงผ่านโดเมน HTTPS และลองอัปโหลดสลิป 1 รายการ เพื่อตรวจว่า Cloudinary แบบ private ทำงาน (ส่วนนี้ทดสอบกับ Cloudinary จริงในเครื่องผู้พัฒนาไม่ได้)

## ข้อจำกัดที่ยังไม่ได้ทำ

- ยังไม่ส่ง SMS/OTP (ลูกค้าดูบัตรผ่านหน้าเว็บแทน; ต้องเลือกผู้ให้บริการ SMS และลงทะเบียนชื่อผู้ส่งก่อน)
- การเช็กอินเป็นระดับ "การจอง" (ทุกโต๊ะของการจองนั้นพร้อมกัน) ยังไม่นับจำนวนคนที่เข้าแล้วต่อโต๊ะ
- ไม่มี CSP และ token ยังอยู่ใน localStorage (ดูหัวข้อความปลอดภัย)
